# Probes state a size, and a harmless control probe runs first

A dry-run create passes through every admission gate, not only the security ones. A ResourceQuota that caps `requests.cpu` rejects any pod with no stated request, and that rejection would look like a PASS for AT-04 and AT-05. So every probe states a request and limit the namespace accepts (see the sizing rule below), and before the dangerous probes the tool dry-runs one compliant control pod. If the control pod is rejected, AT-04 and AT-05 are SKIP with the cluster's reason, because the test cannot prove anything. The rejection text decides the layer: "violates PodSecurity" is admission (PSA), "admission webhook ... denied" is admission (policy engine), a 403 with no admission text is RBAC, and quota or LimitRange text is inconclusive, so SKIP. The alternative, treating any rejection as PASS (what kubectl-mtb did), produces false passes. Amended in the Phase 2 review: RBAC is settled by SSAR before any probe, so a probe rejection is never RBAC, and a 403 without admission text is ERROR (classifier rule 6); a control the classifier calls an API failure is ERROR, not SKIP (D65); a 429 or 5xx answer is ERROR whatever its text (D82, D95).

Sizing rule (CEO review, 2026-10-10): a LimitRange `min` above 1m CPU or 1Mi memory rejects even the control pod, which would turn AT-04 and AT-05 into SKIP on exactly the governed namespaces the tool is for. So probes use the highest `min`, and 1m and 1Mi otherwise or when limitranges cannot be listed. Amended in the Phase 2 review (D85): probes always state their sizes and never rely on LimitRange defaults, because the API server copies `max` into `default` and `defaultRequest`, so an unsized probe asked for the max and a quota with less room rejected the control.

Controller bypass (CEO review, 2026-10-10): when RBAC denies `create pods` but allows creating a pod controller (Deployment, ReplicaSet, StatefulSet, DaemonSet, Job, CronJob, and, since the Phase 2 review, ReplicationController), or adding an ephemeral container to a running pod (`pods/ephemeralcontainers`), the resulting pods are not subject to the tenant's create-pods RBAC and only admission can stop them. Admission was not exercised, so AT-04 reports SKIP with the allowed kind named, not PASS (D66). An RBAC-only PASS also needs the identity to hold some right in the namespace (`list pods`), so a misspelled `--as` user is SKIP, not PASS (D69).

Valid objects (outside review, 2026-10-11): a probe must pass API validation before admission sees it. `privileged: true` with `allowPrivilegeEscalation: false` is rejected at validation, so every privileged probe differs from the control in that field too. AT-04.1 therefore sends two forms, with `allowPrivilegeEscalation` unset (D70) and `true`, and passes only when both are rejected; AT-04.5 sets only `allowPrivilegeEscalation: true` (Phase 2 review, D78). The control's answer must be a dry run (empty `resourceVersion`, a generated name) before any dangerous probe is sent (D79).

Services too (outside review, 2026-10-11): AT-05 rehearses a compliant ClusterIP Service before the NodePort probe. A policy that rejects Services for an unrelated reason (a required label, a naming rule) would otherwise reject the probe and produce a false PASS; when the control Service is rejected, AT-05 is SKIP with the real reason.
